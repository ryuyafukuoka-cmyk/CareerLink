ここがバックエンド

バックエンドに関するファイルはすべて

\backend

のしたに

## 初回セットアップ

```bash
cd backend
npm install
```

## 使えるコマンド

`backend` フォルダで実行します。ルートから実行する場合は `npm run <コマンド> --prefix backend` です。

| コマンド      | 内容                                                                 | いつ使う？               |
| ------------- | -------------------------------------------------------------------- | ------------------------ |
| `npm run dev` | nodemon でサーバーを起動する。ファイルを保存すると自動で再起動される | 開発中（ふだんはこれ）   |
| `npm start`   | `node server.js` でサーバーを起動する。自動再起動はしない            | 動作確認・本番に近い起動 |
| `npm test`    | テストを実行する（まだテストなし）                                   | PR を出す前              |

## 動作確認

`npm run dev` で起動したあと、ブラウザで次の URL を開きます。

```
http://localhost:3000/api/health
```

`{"data":{"status":"ok"}}` と表示されれば正常です。

## メモ

- ポート番号は `3000`（環境変数 `PORT` で変更可能）
- 成功時のレスポンスは `{ "data": ... }` の形式（共通仕様に従う）
- 本番は AWS（Lambda + API Gateway）の予定。この Express サーバーはローカル開発用の仮のもの
- `.env` や DB のパスワード、AWS のキーは絶対にコミットしない

## 仮サーバー（mock-server）

AWS の API ができるまで使う開発専用のサーバーです。12/20 に `backend/mock-server/` ごと削除します。

```bash
npm run dev          # ルートで実行：フロントエンド＋仮サーバーを同時に起動
npm run dev:back     # ルートで実行：フロントエンド＋本来の server.js を起動
npm run dev:mock --prefix backend   # 仮サーバーだけ起動
```

- データは `frontend/src/mocks/` から読み込み、メモリ上だけで動きます（再起動で元に戻る）
- 操作するユーザーは、リクエストヘッダー `X-Mock-User` にユーザーID（`1`〜`7`）を入れて指定します
- 特別な値：`new-student`（卒業年度が未設定の初回ログイン学生）、`ineligible`（利用対象外の拒否）
- ユーザーID `4` は無効化されたユーザーで、ログインは `ACCOUNT_INACTIVE` で拒否されます
- 実装済み：A-01、U-01、U-02、C-01〜C-07

## API Gateway の設定（HTTP API）

Lambda は 1 つ（`lambda.js`）で、Express がパスを振り分けます。API Gateway は次の 2 ルートだけ作れば足ります。

| ルート              | 認可               | 統合                          |
| ------------------- | ------------------ | ----------------------------- |
| `GET /api/health`   | なし               | Lambda プロキシ（payload v2） |
| `ANY /api/{proxy+}` | JWT オーソライザー | Lambda プロキシ（payload v2） |

- JWT オーソライザー：発行者は Cognito ユーザープールの URL、Audience はアプリクライアント ID
- CORS：Amplify の URL を許可し、許可ヘッダーに `Authorization` と `Content-Type`、メソッドに `GET, POST, PUT, PATCH, DELETE, OPTIONS` を入れる。公開ヘッダー（Expose headers）に `Retry-After` も入れる（429 の残り秒数をブラウザが読むため）
- Lambda の環境変数：`.env.example` の項目（`DB_*`、`AD_*`、`DISPLAY_NAME_CLAIM`）。`NODE_ENV=production` にして `devAuthenticate` を使えなくする
- Lambda は RDS と同じ VPC に置く。ハンドラーは `lambda.handler`

## 実装済みの API（`backend/`）

| ID               | API                                                       | ファイル            |
| ---------------- | --------------------------------------------------------- | ------------------- |
| A-01             | `POST /api/auth/login`                                    | `authHandler.js`    |
| U-01〜U-07       | `/api/users/*`                                            | `userHandler.js`    |
| C-01〜C-07       | `/api/companies/*`、`/api/company-options`                | `companyHandler.js` |
| RD-01〜RD-06     | `/api/application-rounds/*`                               | `roundHandler.js`   |
| R-01〜R-09、S-02 | `/api/activity-records/*`                                 | `recordHandler.js`  |
| S-01、S-03       | `GET /api/activity-records`、`/api/graduation-years`      | `searchHandler.js`  |
| K-01〜K-03       | `/api/companies/:id/karte`、`interview-info`、`exam-info` | `karteHandler.js`   |

- 企業の変更（C-04）は企業行をロックして `deletion_version` を加算する。応募回・活動記録の作成・更新・削除を実装するときも、同じ企業行をロックして加算すること（C-06 の 409 判定に必要）
- 操作ログ（F-007-03）は LOG-01〜06 が未確定のため、まだ書き込まない
- 新規登録の30秒制限は `services/creationCooldown.js`（RD-01 は `round`）。R-01 を作るときは `activityRecord` を指定して同じ関数を呼ぶ。ロック順序は「企業行 → 実行者の users 行」
- キーワード検索：部分一致は SQL の LIKE（`%` `_` はエスケープ）。完全一致は SQL で候補を絞ったあと、`Intl.Segmenter('ja')` で単語に分割して判定する（`common/wordMatch.js`）。Lambda の Node が ICU を含むこと（標準の Node 18 以降は含む）
- 未実装：操作履歴（L）
