ここがフロントエンド

フロントエンドに関するファイルはすべて

\frontend

のしたに

## 初回セットアップ

```bash
cd frontend
npm install
```

`.env.example` をコピーして `.env` を作ります（`.env` はコミットしません）。

```bash
copy .env.example .env
```

## 使えるコマンド

`frontend` フォルダで実行します。ルートから実行する場合は `npm run <コマンド> --prefix frontend` です。

| コマンド             | 内容                                                                            | いつ使う？             |
| -------------------- | ------------------------------------------------------------------------------- | ---------------------- |
| `npm run dev`        | 開発サーバーを起動する（http://localhost:5173）。保存すると画面が自動更新される | 開発中（ふだんはこれ） |
| `npm run build`      | 本番用にビルドして `dist/` を作る                                               | デプロイ前の確認       |
| `npm run preview`    | ビルドした結果をローカルで確認する                                              | `build` のあとの確認   |
| `npm run lint`       | ESLint でコードの問題を検出する                                                 | コミット・PR の前      |
| `npm test`           | テストを1回実行する                                                             | コミット・PR の前      |
| `npm run test:watch` | ファイルを保存するたびにテストを再実行する                                      | テストを書いているとき |

## フォルダ構成（src/）

| フォルダ    | 役割                               |
| ----------- | ---------------------------------- |
| `screens/`  | 画面（機能ごとにフォルダを分ける） |
| `auth/`     | ログイン・ログアウト・トークン管理 |
| `api/`      | API を呼び出す処理                 |
| `mocks/`    | AWS ができる前に使う仮データ       |
| `messages/` | 画面に表示するメッセージの文言     |

## 環境変数（.env）

| 変数名               | 内容                                                      |
| -------------------- | --------------------------------------------------------- |
| `VITE_API_BASE_URL`  | API のアドレス（例：`http://localhost:3000/api`）         |
| `VITE_USE_MOCK_AUTH` | `true` で開発用の仮ログイン（ロール切替）、本番は `false` |

`VITE_` で始まる変数だけがフロントエンドから読めます。

## テストの書き方

ファイル名は `〇〇.test.jsx` にします。`describe` `it` `expect` は毎回 `vitest` から import します。

```js
import { describe, it, expect } from 'vitest';
```
